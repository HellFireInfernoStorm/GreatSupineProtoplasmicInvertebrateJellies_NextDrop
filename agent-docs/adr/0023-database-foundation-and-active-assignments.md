# ADR 0023: Database foundation, active assignments and raw SQL migration ownership

- Status: accepted
- Date: 2026-10-03
- Issue / PR: #25
- Designathon departure: no

## Context

The first schema needs every model in [model.md](../spec/data/model.md) and the safeguards in [sql-constraints.md](../spec/data/sql-constraints.md). A PostgreSQL partial index cannot read a trip's status from another table. Publication idempotency also needs the draft revision in each immutable publication. The raw-SQL drift question must be resolved with a real PostgreSQL migration run.

## Decision

Pin `prisma`, `@prisma/client` and `@prisma/adapter-pg` to 7.10.0, with `pg` 8.23.1. Use the Prisma 7 `prisma-client` TypeScript generator, explicit client generation, `prisma.config.ts`, and the PostgreSQL driver adapter. No native client engine or `binaryTargets` is required with this adapter. The migration CLI still uses its schema engine. PostgreSQL remains version 16. These implement the existing approved ORM/database choices.

Each `TripStop` carries `tripStatus`. Its `(tripId, tripStatus)` foreign key references the unique `(Trip.id, Trip.status)` pair with `ON UPDATE CASCADE`. PostgreSQL synchronizes the status when a trip changes and rejects a mismatched status supplied directly. A partial unique index on `TripStop.orderId WHERE tripStatus <> CANCELLED` enforces one non-cancelled assignment, including concurrent writes and reactivation. `COMPLETE` remains non-cancelled: replanning a failed order removes/moves its mutable current stop; immutable plan snapshots preserve historical assignments. Writers must supply the current parent status when inserting/moving a stop (the default is PLANNED).

Prisma's `partialIndexes` preview feature represents this index in the schema so migration drift comparison includes it. The initial migration owns immutability functions/triggers and CHECK constraints. They are recreated by replaying that migration into the shadow database; future migrations must preserve them. Integration tests verify their presence and behavior. `FeedCounter` uses a unique checked `singleton=true` column, receives its sole infrastructure row in the migration, and rejects row deletion. `DemoState` uses the same singleton key but its row is created by the separate seed issue.

`PlanVersion.draftRevision` is unique within its planning day. Reference capacities and demand volumes use Decimal(10,3). Product and OrderLine unit snapshots use Decimal(13,6), preserving milligram/millilitre precision without reducing their original seven integer digits; the explicitly specified `Order.weightG` and `Order.volumeL` remain positive integer totals. UUID v7 defaults are generated by the Prisma client; SQL fixture writers must provide UUIDs. Instants are timestamptz; service dates are date; window, departure and ETA fields use minutes from Asia/Colombo midnight. Reference enum values match the CSVs and rules package.

The existing public `/api/readyz` returns 200 only when the database is reachable and every checked-in migration has a completed, matching-checksum record. Failed or pending attempts return 503, and rolled-back attempts do not count as applied. Prisma is owned by the server lifecycle and disconnects on shutdown. The application Prisma client is exposed as `app.prisma` with no probe-sized query timeout. A separate bounded probe client uses 2s connection/query/statement limits; both clients disconnect on server shutdown. Missing migration directories or SQL files keep health live and readiness unavailable. With no DATABASE_URL the API remains live but unready. Public responses contain check statuses, never connection details.

## Precision proposal and approval gate

Owner review on PR #76 requests finer unit sizes and a decision about integer order totals. The proposal is to sum `qtyOrdered * unit snapshot` with decimal arithmetic, then ceil the final kg * 1000 and m3 * 1000 totals once to positive integer grams/litres. `aggregateOrderQuantities` implements this storage conversion. Do not round each unit before multiplication. One 0.0004 m3 item becomes 1 litre for capacity accounting; three such items become 2 litres, not 3. The exact sizes remain on saved line snapshots for display/audit. This is a proposed exception for fine product-derived order totals to ADR 0018's nearest-thousandth reference-data conversions, which remain unchanged. Owner approval of this ADR is required before merge.

The owner must also confirm these existing-spec choices before accepting this ADR:

- Cancelled trips retain their unique `(planningDayId, vehicleId, tripNo)` slot. Reactivating/updating that existing trip row is the only slot-reuse path; a new replacement trip row is rejected. Immutable events and version snapshots preserve the prior publication. A partial slot index is an alternative requiring an explicit schema/spec change.
- COMPLETE trips remain non-cancelled. A failed order's current stop must be moved/removed before replanning; the completed trip's relational stop list changes, while immutable plan snapshots/events retain history. Preserving every completed relational stop would require a separate active-assignment model or predicate change. Neither alternative is silently selected in this PR.


Merged contracts v1 (PR #75) already defines `subject.vehicleId`; no contract edit or contract-change label is needed here. Storage also permits its SYSTEM actor role and zero-based device sequences. SYSTEM events retain a UUID `actorUserId` FK to an existing audit/automation user (with one of the four login roles); the event role SYSTEM grants no extra login role or authorization. Bare synthetic actor IDs such as "system" are not persisted as user IDs; system producers use that configured audit user's UUID.

Runtime startup uses `tsx` as a production dependency and never generates the client. The build runs `prisma generate`; deployment packaging includes the generated source and migrations. The Prisma CLI remains a build/migration tool, not a prerequisite of `pnpm start`.

## Alternatives considered

- Application-only uniqueness: concurrent writes or alternate writers could bypass it.
- A client-writable active boolean: it could diverge from the trip status.
- Status synchronization triggers with parent row locks: possible, but the cascading composite foreign key provides the same invariant using declarative database constraints.
- Prisma 8 release candidate: no need to take a prerelease major for the foundation.
- Hand-written partial index absent from the Prisma schema: weakens visibility and drift coverage in a version that can represent it.

## Consequences

Spec edits: `data/model.md`, `data/sql-constraints.md`, `data/prisma-rules.md`, `domain/units-and-time.md`, `platform/api.md`, and `open-questions.md` once drift verification succeeds. Schema-dependent work must use the documented field units, and migrations/schema-change PRs still require owner review. Seed data, feature modules and DTOs remain separate issues.
