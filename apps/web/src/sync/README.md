# Field offline core (#40)

Loader and Driver screens import from `src/sync/index.ts`:

- `useFieldSnapshot()` reads the signed-in user's saved snapshot; no screen fetches field data directly.
- `useProjectedOrder(orderId)` folds pending/sending and not-yet-snapshotted accepted facts over the snapshot through `rules.applyEvent`. The returned reducer state is advisory; server confirmation remains authoritative.
- `fieldRepository.enqueue({ type, payload, subject, actor, blobRefs? })` records a durable intent. UUID v7, device sequence, capture time, clock offset and current plan version are allocated inside the IndexedDB transaction. Render a saved confirmation only after this promise resolves.
- `fieldRepository.enqueueBatch(intents, receipt)` commits an outcome, proof and scoped receipt in one transaction. Delivery receipts count deliveries rather than individual events and survive covering-snapshot pruning, including server confirmation times. Plan acknowledgement receipts also survive pruning; pending, held or rejected acknowledgements do not mark a plan accepted. Epoch reset clears these receipts and Driver plan baselines.
- `queuePhoto(blob, userId)` compresses evidence before storage and returns the client blob ID for the event payload. Text and binary queues retry independently; text is sent first.
- `useSyncDiagnostics()` exposes pending work, rejected records/reasons, held facts and last server-aware sync time. `syncController.syncNow()` is the manual trigger. `setForceOffline()` persists the field-session demo switch, cleared on sign-out/session loss.

`FieldSync` owns foreground listeners in the field shell, the PIN prompt and diagnostics. It uses the existing session and CSRF APIs. Reloads restore only validated Loader/Driver sessions; a network failure keeps the shell without asking for PIN; only a server 401 pauses sync and asks for PIN. Wrong PIN/lockout leaves the session/work intact. Nonrenewable authentication or logout removes authentication; queued work remains bound to its original user and is not replayed by another account.

Optional session/preferences persistence and device initialization fall back when IndexedDB cannot open, so online authentication remains usable. Durable field writes still require storage and must succeed before the screen confirms work was saved.

The controller owns one flight per tab and one cross-tab owner per database (Web Locks, with a renewable IndexedDB lease fallback). Interrupted sending rows retry with their original IDs. A correlated ACCEPTED/DUPLICATE/HELD_CONFLICT/REJECTED result is required before an event stops counting as pending. Held and failed records stay visible. ACCEPTED/DUPLICATE rows carry the confirmation feedHead and stay projected until snapshot replacement atomically prunes rows whose head is covered. Ordinary pull cursor advancement alone never prunes them. Legacy acknowledgements without a confirmation boundary remain retained. Indexed per-user/state reads exclude unrelated accounts and completed history from diagnostics and replay. Batch sizing uses the contract body limit and a running UTF-8 byte count. Foreground triggers received during a flight request a joined immediate pass and reset backoff. Push feedHead is never a pull cursor. Empty audience-filtered pages advance to head; full pages use the last item's string sequence. Changed pages trigger one atomic snapshot replacement, keeping the outbox. Epoch changes are checked before replay, and explicitly discard pre-reset data under ADR 0007.

The Vite Workbox build precaches the shell, role chunks, local fonts, locales and icons; `/api` never falls through to the cached shell. The update prompt requires explicit confirmation of an idle/between-stops moment and disables activation during sync. Tests use fake-indexeddb; production-browser verification must use `pnpm build` and `pnpm preview`, because the worker is intentionally disabled in development.

Held facts are reconciled on every pull through `POST /sync/conflicts` (ADR 0043), asked by `clientEventId` and independent of the feed cursor. A `conflict_resolved` hint only triggers a pass, so a missed hint or a cold resume recovers the same way.

- **Accepted:** the fact becomes `acked` with the response `feedHead` as its confirmation boundary, so it stays projected until a covering snapshot.
- **Rejected:** the fact becomes `rejected` (`CONFLICT_REJECTED`) and keeps the decision and the dispatcher's note for diagnostics.
- **Open, unknown or unreachable:** the fact stays held. A failed outcome request never blocks pushing.

Server endpoints and field screens remain separate issues. `VITE_API_MOCK=true` uses the contract fixtures, with correlated acknowledgements for the submitted event IDs. Mock snapshots are static examples and do not simulate a complete evolving backend.

Driver requests `includeContext: true` on conflict lookup (ADR 0044). Owned open context is stored in `conflictsLocal`, survives current snapshot replacement and cold resume, and is retained alongside later decisions. An opted-in epoch change discards stale history before replay. Driver R3 displays the original fact, capture/receipt times and recorded publication changes without inferring cancellation or a reason from the current snapshot. Missing historical fields remain explicit.

Driver routes `/driver`, `/driver/stop/:stopId`, `/driver/sync` and `/driver/settings` consume only Dexie. The shared field controller and PIN prompt remain mounted while its generic diagnostics are replaced by Driver screens. The sync badge and All synced screen wait for covering snapshots as well as text/blob confirmations. A received clash stays labelled Needs dispatch, with its evidence and inert local projection; All synced counts server receipt, never dispatcher acceptance. Plan review appears after queued work and clash context have reconciled; its receipt confirms only after the acknowledged boundary is covered. Adjacent outlet cards preserve independent order links and completion; durable local completion is advisory until server reconciliation.
